2 Parte 2 — Verificar y Completar el Script SQL

2.1 Paso 4: Análisis de ON DELETE — Respuesta esperada

FK ON DELETE generado ¿Es correcto? Justificación
ventas.cliente_id → clientes RESTRICT Sí No se debe eliminar un cliente con historial de ventas. La eliminación debe bloquearse para preservar trazabilidad financiera y auditoría.
detalle_ventas.venta_id → ventas RESTRICT No — debe ser CASCADE Si se cancela o elimina una venta, sus líneas de detalle no tienen sentido sin la cabecera. El CASCADE elimina automáticamente los ítems al borrar la venta, evitando registros huérfanos.
despachos.venta_id → ventas RESTRICT Sí No se puede eliminar una venta que ya tiene un despacho registrado. El registro logístico es parte del historial operacional.
devoluciones.venta_id → ventas RESTRICT Sí No se puede eliminar una venta con devoluciones asociadas. El registro de devoluciones tiene impacto contable y no debe perderse.
Tip

Para el docente: el único CASCADE semánticamente justificado es en detalle_ventas. Use este punto para discutir la pregunta: “¿Los datos hijos tienen sentido independientemente del padre?”. Si la respuesta es no → CASCADE. Si la respuesta es sí (el hijo tiene valor propio aunque el padre no exista) → RESTRICT o SET NULL.

Penalizar si los estudiantes usan CASCADE en ventas.cliente_id — ese error destruye el historial de ventas de un cliente si alguien borra por error un registro de la tabla clientes.

Script DDL completo corregido — Respuesta modelo:

-- ============================================================
-- TECHSTYLE — Script DDL completo con ajustes manuales
-- Generado con MySQL Workbench 8.0
-- ============================================================

SET @OLD_UNIQUE_CHECKS=@@UNIQUE_CHECKS, UNIQUE_CHECKS=0;
SET @OLD_FOREIGN_KEY_CHECKS=@@FOREIGN_KEY_CHECKS, FOREIGN_KEY_CHECKS=0;
SET @OLD_SQL_MODE=@@SQL_MODE,
    SQL_MODE='ONLY_FULL_GROUP_BY,STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION';

CREATE SCHEMA IF NOT EXISTS `techstyle`
    DEFAULT CHARACTER SET utf8mb4
    COLLATE utf8mb4_spanish_ci;
USE `techstyle`;

-- ── 1. categorias (FK auto-referencial) ────────────────────
DROP TABLE IF EXISTS `categorias`;
CREATE TABLE IF NOT EXISTS `categorias` (
    `categoria_id`       INT          NOT NULL AUTO_INCREMENT,
    `nombre_categoria`   VARCHAR(50)  NOT NULL,
    `descripcion`        VARCHAR(200) NULL,
    `categoria_padre_id` INT          NULL,
    PRIMARY KEY (`categoria_id`),
    INDEX `fk_categoria_padre_idx` (`categoria_padre_id` ASC),
    CONSTRAINT `fk_categoria_padre`
        FOREIGN KEY (`categoria_padre_id`)
        REFERENCES `categorias` (`categoria_id`)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;
SHOW WARNINGS;

-- ── 2. clientes ────────────────────────────────────────────
DROP TABLE IF EXISTS `clientes`;
CREATE TABLE IF NOT EXISTS `clientes` (
    `cliente_id`     INT          NOT NULL AUTO_INCREMENT,
    `nombre`         VARCHAR(50)  NOT NULL,
    `apellido`       VARCHAR(50)  NOT NULL,
    `email`          VARCHAR(100) NOT NULL,
    `region`         VARCHAR(50)  NOT NULL,
    `segmento`       VARCHAR(20)  NULL,
    `fecha_registro` DATE         NOT NULL,
    PRIMARY KEY (`cliente_id`),
    UNIQUE INDEX `email_UNIQUE` (`email` ASC)
) ENGINE=InnoDB;
SHOW WARNINGS;

-- ── 3. proveedores ─────────────────────────────────────────
DROP TABLE IF EXISTS `proveedores`;
CREATE TABLE IF NOT EXISTS `proveedores` (
    `proveedor_id`     INT          NOT NULL AUTO_INCREMENT,
    `nombre_proveedor` VARCHAR(100) NOT NULL,
    `rut`              VARCHAR(12)  NOT NULL,
    `contacto`         VARCHAR(100) NULL,
    `email`            VARCHAR(100) NULL,
    `telefono`         VARCHAR(20)  NULL,
    PRIMARY KEY (`proveedor_id`),
    UNIQUE INDEX `rut_UNIQUE` (`rut` ASC)
) ENGINE=InnoDB;
SHOW WARNINGS;

-- ── 4. productos (FK → categorias) ─────────────────────────
DROP TABLE IF EXISTS `productos`;
CREATE TABLE IF NOT EXISTS `productos` (
    `producto_id`     INT            NOT NULL AUTO_INCREMENT,
    `nombre_producto` VARCHAR(100)   NOT NULL,
    `categoria_id`    INT            NOT NULL,
    `precio_venta`    DECIMAL(10,2)  NOT NULL,
    `costo_unitario`  DECIMAL(10,2)  NOT NULL,
    `stock`           INT            NOT NULL DEFAULT 0,
    `activo`          TINYINT(1)     NOT NULL DEFAULT 1,
    PRIMARY KEY (`producto_id`),
    INDEX `fk_productos_categorias_idx` (`categoria_id` ASC),
    CONSTRAINT `fk_productos_categorias`
        FOREIGN KEY (`categoria_id`)
        REFERENCES `categorias` (`categoria_id`)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;
SHOW WARNINGS;

-- ── 5. ventas (FK → clientes) ──────────────────────────────
DROP TABLE IF EXISTS `ventas`;
CREATE TABLE IF NOT EXISTS `ventas` (
    `venta_id`   INT  NOT NULL AUTO_INCREMENT,
    `fecha`      DATE NOT NULL,
    `cliente_id` INT  NOT NULL,
    PRIMARY KEY (`venta_id`),
    INDEX `fk_ventas_clientes_idx` (`cliente_id` ASC),
    CONSTRAINT `fk_ventas_clientes`
        FOREIGN KEY (`cliente_id`)
        REFERENCES `clientes` (`cliente_id`)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;
SHOW WARNINGS;

-- ── 6. detalle_ventas (FK → ventas CASCADE, productos RESTRICT)
DROP TABLE IF EXISTS `detalle_ventas`;
CREATE TABLE IF NOT EXISTS `detalle_ventas` (
    `venta_id`        INT           NOT NULL,
    `producto_id`     INT           NOT NULL,
    `cantidad`        INT           NOT NULL,
    `precio_unitario` DECIMAL(10,2) NOT NULL,
    `descuento_pct`   DECIMAL(5,2)  NULL DEFAULT 0,
    PRIMARY KEY (`venta_id`, `producto_id`),
    INDEX `fk_detalle_productos_idx` (`producto_id` ASC),
    CONSTRAINT `fk_detalle_ventas`
        FOREIGN KEY (`venta_id`)
        REFERENCES `ventas` (`venta_id`)
        ON DELETE CASCADE ON UPDATE CASCADE,  -- único CASCADE justificado
    CONSTRAINT `fk_detalle_productos`
        FOREIGN KEY (`producto_id`)
        REFERENCES `productos` (`producto_id`)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;
SHOW WARNINGS;

-- ── 7. proveedor_producto (FK → proveedores, productos) ────
DROP TABLE IF EXISTS `proveedor_producto`;
CREATE TABLE IF NOT EXISTS `proveedor_producto` (
    `proveedor_id`        INT           NOT NULL,
    `producto_id`         INT           NOT NULL,
    `precio_compra`       DECIMAL(10,2) NOT NULL,
    `plazo_entrega_dias`  INT           NULL,
    `proveedor_principal` TINYINT(1)    NOT NULL DEFAULT 0,
    PRIMARY KEY (`proveedor_id`, `producto_id`),
    INDEX `fk_pp_productos_idx` (`producto_id` ASC),
    CONSTRAINT `fk_pp_proveedores`
        FOREIGN KEY (`proveedor_id`)
        REFERENCES `proveedores` (`proveedor_id`)
        ON DELETE RESTRICT ON UPDATE CASCADE,
    CONSTRAINT `fk_pp_productos`
        FOREIGN KEY (`producto_id`)
        REFERENCES `productos` (`producto_id`)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;
SHOW WARNINGS;

-- ── 8. despachos (1:1 con ventas via UNIQUE) ───────────────
DROP TABLE IF EXISTS `despachos`;
CREATE TABLE IF NOT EXISTS `despachos` (
    `despacho_id`            INT          NOT NULL AUTO_INCREMENT,
    `venta_id`               INT          NOT NULL,
    `direccion_entrega`      VARCHAR(200) NOT NULL,
    `fecha_despacho`         DATE         NULL,
    `fecha_entrega_estimada` DATE         NULL,
    `fecha_entrega_real`     DATE         NULL,
    `estado`                 VARCHAR(20)  NOT NULL DEFAULT 'Pendiente',
    PRIMARY KEY (`despacho_id`),
    UNIQUE INDEX `venta_id_UNIQUE` (`venta_id` ASC),
    CONSTRAINT `fk_despachos_ventas`
        FOREIGN KEY (`venta_id`)
        REFERENCES `ventas` (`venta_id`)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;
SHOW WARNINGS;

-- ── 9. devoluciones (FK → ventas, productos) ───────────────
DROP TABLE IF EXISTS `devoluciones`;
CREATE TABLE IF NOT EXISTS `devoluciones` (
    `devolucion_id`     INT           NOT NULL AUTO_INCREMENT,
    `venta_id`          INT           NOT NULL,
    `producto_id`       INT           NOT NULL,
    `fecha_devolucion`  DATE          NOT NULL,
    `cantidad_devuelta` INT           NOT NULL,
    `motivo`            VARCHAR(200)  NULL,
    `estado`            VARCHAR(20)   NOT NULL DEFAULT 'Pendiente',
    `monto_reembolsado` DECIMAL(10,2) NULL,
    PRIMARY KEY (`devolucion_id`),
    INDEX `fk_dev_ventas_idx`    (`venta_id`    ASC),
    INDEX `fk_dev_productos_idx` (`producto_id` ASC),
    CONSTRAINT `fk_devoluciones_ventas`
        FOREIGN KEY (`venta_id`)
        REFERENCES `ventas` (`venta_id`)
        ON DELETE RESTRICT ON UPDATE CASCADE,
    CONSTRAINT `fk_devoluciones_productos`
        FOREIGN KEY (`producto_id`)
        REFERENCES `productos` (`producto_id`)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;
SHOW WARNINGS;

SET SQL_MODE=@OLD_SQL_MODE;
SET FOREIGN_KEY_CHECKS=@OLD_FOREIGN_KEY_CHECKS;
SET UNIQUE_CHECKS=@OLD_UNIQUE_CHECKS;

-- ── CHECK constraints (agregar después de todos los CREATE TABLE)
ALTER TABLE productos       ADD CONSTRAINT chk_precio_positivo   CHECK (precio_venta > 0);
ALTER TABLE productos       ADD CONSTRAINT chk_costo_positivo    CHECK (costo_unitario > 0);
ALTER TABLE productos       ADD CONSTRAINT chk_stock_no_negativo CHECK (stock >= 0);
ALTER TABLE detalle_ventas  ADD CONSTRAINT chk_cantidad_positiva CHECK (cantidad > 0);
ALTER TABLE detalle_ventas  ADD CONSTRAINT chk_descuento_rango   CHECK (descuento_pct BETWEEN 0 AND 100);
ALTER TABLE clientes        ADD CONSTRAINT chk_segmento_valido   CHECK (segmento IN ('Premium', 'Estándar', 'Básico'));
ALTER TABLE despachos       ADD CONSTRAINT chk_estado_despacho   CHECK (estado IN ('Pendiente', 'En tránsito', 'Entregado', 'No entregado'));
ALTER TABLE devoluciones    ADD CONSTRAINT chk_estado_devolucion CHECK (estado IN ('Pendiente', 'Aprobada', 'Rechazada'));

-- ── Índices de rendimiento
CREATE INDEX idx_clientes_region     ON clientes(region);
CREATE INDEX idx_clientes_segmento   ON clientes(segmento);
CREATE INDEX idx_ventas_fecha        ON ventas(fecha);
CREATE INDEX idx_productos_categoria ON productos(categoria_id);
CREATE INDEX idx_despachos_estado    ON despachos(estado);

Respuesta a la pregunta del Paso 11: > ¿Cómo identifica esta consulta cuáles son las categorías raíz y cuáles son subcategorías?

Las categorías raíz tienen categoria_padre_id = NULL (sin padre). Las subcategorías tienen un valor entero en categoria_padre_id que referencia el categoria_id de su categoría padre. El ORDER BY categoria_padre_id, categoria_id agrupa primero los NULL (raíces) y luego las subcategorías en orden de padre.

Para el docente: errores frecuentes en el INSERT de Carlos: 1. 7 Notas para el docente

Sobre la evaluación del script DDL (Partes 1–2):

Los tres puntos críticos a verificar: 1. Orden correcto de tablas — categorias, clientes, proveedores antes de las dependientes. Error frecuente: categorias después de productos. 2. ON DELETE CASCADE en detalle_ventas.venta_id — es el único lugar semánticamente justificado. Deducir puntos si usan CASCADE en ventas.cliente_id (destruye historial). 3. CHECK constraints y DROP TABLE IF EXISTS — sin DROP, el script falla en la segunda ejecución; sin CHECK, los datos pueden quedar en estados inválidos.

Sobre la ejecución en MySQL (Parte 3):

Los errores más frecuentes: - ERROR 1215: Cannot add foreign key constraint → tipos de datos incompatibles entre PK y FK (ej. FK es VARCHAR cuando la PK es INT). - ERROR 1050: Table already exists → olvidaron el DROP TABLE IF EXISTS. Solución: ejecutar DROP DATABASE techstyle; CREATE DATABASE techstyle; y re-ejecutar. - El estudiante ejecuta solo la sentencia seleccionada (⚡ vs ⚡⚡) → enseñar la diferencia entre “ejecutar línea actual” y “ejecutar script completo”.

Sobre el INSERT de Carlos (Paso 15):

Variaciones aceptables: - Usar LAST_INSERT_ID() directamente (sin variable) si se ejecutan los dos INSERT en orden sin ningún otro INSERT de por medio. - Hardcodear el venta_id = 3 si el estudiante verificó que esa es la tercera venta — señalar que es frágil pero no penalizar si el resultado es correcto.
